# 共同生活史与体育经历整合版 v0.7

**v0.8 补充：** 当前一般生活清单已恢复为博导原版 52 条，原 24 条候选提示停用但旧记录保留；年龄/年级点击选择，画树前增加原版示范与练习。当前变更及备份键以 [v0.8 实现说明](mentor_alignment_v0.8.md) 为准，下文保留 v0.7 的共同数据契约。

本文件是当前交互与导出契约，优先于旧版仅体育事件的分流说明。研究主线为体育训练、比赛及获奖暴露与大学生心理韧性、焦虑、抑郁的关联；一般生活史提供背景和过程信息。

## 共同流程

背景 → 一般生活与体育专项事件选择 → 多领域标签与同一事件去重 → 一棵共同生命树 → 共同情境与条件专项题 → 检查、二维/三维查看及导出。

- 一般生活清单对所有学生开放；24 条候选提示覆盖家庭、学业、人际、健康、环境转变和成长，正负各 12 条。
- 原有体育 24 条的 ID 保持不变。只有明确有比赛或专项训练经历时开放体育专项清单。没有专项经历者仍可通过一般清单或自填记录体育课、日常运动。
- 清单按领域折叠；未勾选不能直接解释为已经确认未发生。每件选中的事件均绘图并获得同一组共同题，不只详细追问第一件或影响最大的一件。无正负配额，也不按影响排序。
- 未选择任何事件时，所有学生都需区分 `none_recalled` 与 `prefer_not_to_answer`，随后跳过事件页。一般生活史不再使用 `not_applicable_no_exposure`。
- 比赛/专项训练的暴露四组保留。体育专项模块中，无暴露、未回忆起事件、不愿回答分别保存，不能合并成“零影响”。体育课或日常运动不自动升级为专项训练暴露。

## 事件单位与去重

`id` 是唯一事件 ID，`source_scope`/`source_scopes` 表示来自哪组提示，`source_catalog_ids` 保存选中条目的来源。`domains` 可多选家庭、学业、人际、健康、生活转变、个人成长，体育标签由被试确认的体育关系补充。清单来源不是体育关系的正式回答。

`sports_relation` 可为 `none`、`training`、`competition`、`training_and_competition`、`everyday_activity`、`sports_unspecified`（确定与体育有关但场景说不清）、`uncertain`（是否相关说不清）。每件事件需明确操作确认，记录 `relation_confirmed=true`。不会根据体育专业或队伍身份推定事件关系。

同一件事出现在不同清单时，可以选择目标事件进行合并。被试确认目标事件的正负归属及保留其轨迹、原答；双方原始事件与情境完整写入 `merge_history.originals`，来源和领域合并，发生冲突的体育关系需要重新确认。不同时间发生的同类事件不应合并，可以自填注明哪一次。

合并后 `events` 只保留一件；原始 `recall_log` 不改写。`recall_order` 保留目标原记录的次序，`merged_recall_orders` 记录双方原始回忆次序。`first_recall_event` 保留最初记录 ID，`first_recall_canonical_id` 映射到合并后的现存事件；若已移除则为空。首次勾选只是回忆顺序的代理。

## 共同题与专项题

共同字段为 Where、Who、Why、How、故事中心性、当前显著性，以及涉及他人时的亲近/信任程度。体育相关事件在共同选项中增加教练、队友、训练场、比赛场等选项；旧原答若不在新选项中仍可显示，不被静默替换。

- 专项训练事件：训练阶段、训练自主程度。
- 比赛事件：本次比赛层级、比赛或选拔结果；来自获奖提示或明确选择获奖（含自填事件）时，可补本次获奖层级。获奖原答与背景或所选提示矛盾时需返回核对。
- 训练或比赛事件：安排/机会公平感、是否涉及运动伤病；明确涉及伤病时可填完全停训天数。
- 确定与体育有关但具体场景说不清的事件仍可保存轨迹，不据此凭空补训练或比赛字段。

所有滑块保留原有温和配色、一题一行和立体推子。新滑块未经操作不保存中点分数。缺失评分、真实零分、不适用分别处理。共同题当前允许留空，导出 `unanswered_core_fields`，正式必答规则尚需研究方案确定。

背景新增选填训练开始年龄、累计年数、当前或最后一段训练的每周天数/每次分钟数、最高比赛/获奖层级；生命树事件数不能替代这些暴露指标。`training_timing` 按完整轨迹与自报首次训练年龄，分为训练前、训练开始后、跨训练开始、未知或无训练不适用。这只是回顾时间标签，不是因果排序或实际连续训练病程。

## 共享生命树与查看

绘图继续使用博导原版二维核心、年龄轴、影响尺度、跨轴规则及紫正绿负配色，所有事件按同一顺序画在一棵树上。结果页以同一坐标函数回放已完成的有符号路径，并接入博导原版三维查看器。

结果可按全部、一般生活（确认非体育）、体育相关切换，并按单个领域进一步筛选。关系不明者保留在全部中，不能归入非体育。领域重叠只影响查看，不能把各领域数目简单相加。筛选不改变 `events`、绘图顺序或导出范围；二维与三维使用同一筛选结果。

原版三维使用 |r| 与固定效价半区，跨轴方向仍以二维及 JSON 为准；黄色 +1 年外推仅为原版几何演示。

## 旧草稿与数据边界

沿用原 localStorage key，不清空旧事件。首次升级先将原 JSON 备份至 `sports-life-tree-prototype-v0.1-before-v0.7`，保留旧轨迹和情境，返回事件页确认体育关系并补充生活史。若无法额外保存备份会提示及时下载。旧版三项默认评分无法确认是否真实操作，原值保留于 `details_raw`，来源记为 `legacy_unverified`；在被试重新操作前，规范字段为空，不冒充自评。

`details_raw` 保留当前事件的原始情境；规范 `details` 按适用条件输出，不适用为 null，并附 `sports_module_status`。不从一般生活事件推断可控感或客观常模严重度，不把未选提示全记为暴露零。

生活史变量不能一律当协变量：训练前背景、体育参与后的人际支持或伤病等，应依据具体问题与时间假设分别考虑混杂、路径或结局，不凭横断面数据确立中介因果关系。

正式心理量表仍未接入，所有学生保留相同的结果变量接口，`outcome_scales_status=not_integrated`。本工具候选清单不是完整 ASLEC、CTQ，也未证实优于既有量表。线上只提供静态代码，回答仍留在浏览器。

## 验证

安装开发依赖后运行 `npm test` 或 `pnpm test`。几何测试执行实际原版绘图核心；新增模型测试覆盖整合分流、合并和迁移；DOM 集成测试执行实际页面脚本，覆盖无体育暴露者选事件/进入绘图/情境/检查、零评分、条件题、合并、筛选不改原记录、升级前备份。DOM 测试不等于真实浏览器材质、拖动或手机视觉验证。
