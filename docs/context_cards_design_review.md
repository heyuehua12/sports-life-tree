# 第四步情境卡片：设计与检查记录

本轮将第四步的经历改为独立卡片，保留核心题干、选项、题目顺序、体育条件分支、生命树映射和导出结构。

## 使用的三个技能

- `frontend-design`：读取本机 `.workbuddy/plugins/marketplaces/codebuddy-plugins-official/plugins/frontend-design/SKILL.md`，用于卡片层次、颜色与细节一致性。
- `ui-ux-pro-max`：读取本机同一 marketplace 的 `external_plugins/ui-ux-pro-max-skill/skills/ui-ux-pro-max/SKILL.md`，运行其设计系统、UX 与前端建议搜索，采用触控尺寸、对比、焦点、间距和响应式建议。研究问卷继续使用本地中文字体与现有紫绿语义配色。
- `web-design-reviewer`：本机未找到，读取 [GitHub 公开技能原版](https://github.com/github/awesome-copilot/blob/main/skills/web-design-reviewer/SKILL.md) 及其 `visual-checklist.md`、`framework-fixes.md`，执行修改前后截图、DOM 布局及交互复查。

## 设计落地

- 电脑双列，959px 及以下单列；按原经历顺序排列，避免瀑布流改变阅读顺序。
- 卡片头显示编号、原事件名称、正负属性、领域及体育关系。紫色表示正向、绿色表示负向，同时用文字提示，避免只依赖颜色。
- 卡片内分为“发生情境、原因与变化、主观感受”，适用时增加体育专项信息。所有适用选项保持展开。
- 每道滑块题独占一行，保留立体调音推子。初始位置仍不自动记为答案。
- 顶部增加经历名称跳转；点击后对应卡片有边框提示。
- 条件题重绘后恢复当前选项的键盘焦点，并补偿页面滚动位置，避免回答后跳回上方。
- 样式限定在第四步，不改变生命树绘图、3D 展示和第二步卡片。

## 验证结果

通过本地浏览器使用三个明确标注“模拟”的事件验证。测试页面采用独立存储键，未读取或覆盖正式问卷草稿；临时页面在提交前删除，模拟回答不随仓库发布。

已检查修改前后截图、长题干换行、事件顺序、单行滑块和手机排版。浏览器交互确认：

- 切换关键人物后，亲近／信任题中的人物名称同步更新，焦点留在新选项。
- 新增人物多选后，关键人物候选同步增加，焦点留在被点击的选项。
- 伤病“否”隐藏停训天数，“是”重新展开；已有 0 天正确保留。
- 未调整的评分仍显示“未作答”，与 0 分区分。

语法检查与八组项目测试通过；在流程测试中增加条件题重绘后芯片与单选控件焦点保留的回归断言。此轮仅验证原型交互与呈现，不替代测量工具效度检验。
